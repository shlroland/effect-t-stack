# Surfaces that assume a golden copy

Research note for [Research: ETS surfaces that assume golden copy](https://github.com/shlroland/effect-t-stack/issues/3), part of [L3: BTS-mode template source of truth](https://github.com/shlroland/effect-t-stack/issues/1).

Question: which code, scripts, CI, publish packing, docs, and tests still assume a whole-tree copy of `examples/golden` (or treat golden as the permanent source of truth), and what has to change before golden can be deleted?

Inventory taken while switching `create` onto `packages/template-generator` ([Task: Switch CLI create from golden copy to generator](https://github.com/shlroland/effect-t-stack/issues/6)). Golden stays in the repo. Deleting it is [Task: Delete golden and rewrite SoT docs](https://github.com/shlroland/effect-t-stack/issues/8).

## Switched off the golden copy in this change

| Surface                               | Was                                                                                                             | Now                                                                                                                                                                        |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/cli/src/create/create.ts`       | `planCopy` / `executeCopy` of `examples/golden`, then `@ets` → `@<project>` rename and `stampCreateFingerprint` | `generate` + `writeTree` from `@effect-t-stack/template-generator` (`EMBEDDED_TEMPLATES`). Scope is already `@{{projectName}}` in the templates.                           |
| `create-json`                         | Same `createProject`                                                                                            | Same generator path.                                                                                                                                                       |
| `apps/cli/src/create/resolveScope.ts` | Required `examples/golden` (or `ETS_GOLDEN_ROOT` / packed `templates/golden`) to exist                          | Resolves cwd + package scope only. `CreateOptions.goldenRoot` is ignored.                                                                                                  |
| `apps/cli/scripts/pack-golden.ts`     | Copied `examples/golden` into `apps/cli/templates/golden` on `prepack`                                          | Replaced by `scripts/pack-generator.ts`, which prebuilds and copies `packages/template-generator` into `apps/cli/templates/template-generator`. `pack:golden` is an alias. |
| CLI generated-build                   | `createProject` then `check-types`, which copied golden                                                         | Same test file, now the template-based `--yes` path. CI runs it with `ETS_GENERATED_BUILD=1`.                                                                              |

`add` / `add-json` never copied golden files. They only ensure a fingerprint entry for addons that default create already includes (`GOLDEN_ADDONS`). The success message no longer says the files came from a golden copy. A real `add` that reseeds a VFS from the existing project is still future work (Better-T-Stack `add` shape); it is not a golden copy.

`apps/cli/src/create/copyGolden.ts` (`planCopy`, `executeCopy`) is still in the tree and still exported. `create` does not call it. Remove it with the golden delete.

## What has to change to delete golden

Tracked as [Task: Delete golden and rewrite SoT docs](https://github.com/shlroland/effect-t-stack/issues/8). Not done here.

1. Stop installing and `check`ing `examples/golden` in root scripts and `.github/workflows/check.yml`. The scaffold check becomes CLI + template-generator, with generated-build as the `--yes` proof.
2. Drop the parity test and the catalog-equality test, or point them at `dependencyVersionMap` only. One pin table remains.
3. Rewrite `AGENTS.md`, `GLOSSARY.md`, `docs/fingerprint.md`, `docs/CAPABILITY-TIERS.md` (L3 exit vs backlog), `docs/golden-boundaries.md`, and the ADRs that say the sample is copied or edited first. Ownership becomes: edit the template fragment or the post-processor, then prove with a generated-build.
4. Delete `examples/golden` (including the `repos` symlink used only by golden lint). `repos/effect` at the repo root stays a read-only Effect reference until something else replaces that.
5. Remove `copyGolden.ts`, `resolveGoldenRoot`, the copy denylist, and `stampCreateFingerprint` if nothing else calls them. Keep `add`'s allowlist of default addons, renamed off "golden" if the word is retired.
6. effect-style’s oxlint plugin used to point at `./repos/effect/...`. [L3.1: Own effect-style package instead of referencing repos/effect](https://github.com/shlroland/effect-t-stack/issues/11) moves that plugin to `packages/effect-oxc`. `repos/effect` stays a read-only Effect reference.

`add` does not need a golden tree to keep working for the default addons. Deleting golden does not by itself implement non-default Option Matrix cells.
